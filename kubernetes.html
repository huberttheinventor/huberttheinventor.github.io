Kubernetes has never started a container.

Not once. It is a control plane — the part of the system that decides and gives orders. Somewhere below it, on a machine it never touches, a much smaller program does the only real work in the whole picture: it starts the container.

The whole mental model, one picture. Everything after it is annotation.

Take it with you: the map as an image · as a vector

Nº001

It decides. It never touches a container.

The control plane is the brain of the cluster: it watches everything, holds the plan, and decides which containers should exist, where, and how many copies. When something dies, it notices and issues a new order. What it never does, under any circumstance, is run a container itself. That part of the job belongs entirely to something else.

That split has a name — control plane and data plane — and it shows up in almost every large distributed system, not only Kubernetes: one part decides, a different part executes, and the two are built, scaled, and allowed to fail separately.

Nº002

The hands are local, one pair per machine

Every machine in the cluster runs a small agent called a kubelet. It takes orders from the control plane over the network, and it is the only thing standing close enough to a container to actually start one. The order can travel from anywhere; the starting always happens on the spot.

On the map, the dashed line is the order arriving from far away. The short solid line is the kubelet doing the one thing the control plane cannot: reaching down and touching the container.

Nº003

Different jobs, not competing tools

Docker builds a container image and can run it, on one machine, right there. That is the entire job, and it does it well. Kubernetes doesn't replace that step — it sits above many machines, each already capable of running containers, and decides which one runs what, and what happens the moment one of them fails.

Docker executes. Kubernetes orchestrates. The kubelet on each machine drives the same kind of container engine Docker itself is built on, so even inside a cluster, Docker's job never went away. It just stopped being the thing deciding where anything runs.
