Every paid tool has an open twin.

Almost nothing you pay a monthly fee for is the only version of itself. Somebody rebuilt it in public, put the source on GitHub, and let anyone run it. The awkward part was never finding out that these exist; it was finding out which one of the nine competing rebuilds is actually maintained. That is what a directory is for.

Companion to the reel · Watch it on @huberttheinventor

OpenAlternative keeps score. You give it the paid tool, it gives you the open-source projects that do roughly the same job, each with its GitHub star count so you can rank them yourself. Stars are a crude signal, but they are a public one, and a project with a hundred thousand of them is at least being looked at by people who would complain loudly if it broke.

Twelve swaps are listed below. Every pairing was checked against the directory and against the project's own repository, and every star count was read from the GitHub API on 29 August 2026. Numbers move; treat them as a snapshot, not a fact about today.

Three of these, OpenCode, Open WebUI and Cline, are agents or chat interfaces rather than products, and two of them sit at the top of the list. The fastest-moving open-source category right now is the one built on top of models that are themselves not open, which is its own kind of dependency: OpenCode and Cline still need an API key from somebody.

How to judge one before you commit

Five checks, in the order they save you time.

Stars, but only as a floor. Stars measure attention, not quality, and they never go down when a project dies. They are useful for one thing: a project with two hundred stars and no company behind it is a bet, and a project with fifty thousand has enough people watching that a serious bug gets found. Use it to exclude, not to choose.

Last commit date. The single most predictive number on the repo page, and the one nobody reads. Open the repository and look at when the default branch was last pushed. Every project listed above had been pushed to within the previous two days when this page was written. Anything quiet for six months is a project you are adopting, not a tool you are using.

The licence. MIT and Apache-2.0 let you do essentially anything. GPL and AGPL are still open source but carry obligations if you distribute or host a modified version, which matters if this is going into a product. And a growing number of projects use licences that are not open source at all. Two on this list qualify. n8n is "fair-code" under a Sustainable Use License, which permits use for your own internal business purposes and for non-commercial use, and does not permit redistributing or selling it commercially. Read the licence file before you build a business on top of one.

Self-hosted or hosted. Most of these offer both. Self-hosting is where the savings are and where the work is. A hosted plan from the same maintainers is often cheaper than the tool you are leaving and involves no servers, which for one person is usually the right answer even though it feels like cheating.

The trade you are actually making. Setup measured in evenings rather than minutes. A feature list that is close but not identical, and the gap is usually the thing you happen to use daily. No support contract, so when it breaks at 4pm you are reading a GitHub issue thread from 2024, not opening a ticket.

The part the list does not tell you

Three ways this goes wrong, said plainly.

Free to use is not free to run. The software costs nothing. The server does not. Something like Immich holding a decade of photos wants storage, backups of that storage, and a machine that stays on. A small cloud instance plus object storage lands in the same range as the subscription you cancelled, and now you are also the person who gets paged. Self-hosting trades money for time, and time is not free either. It is a good trade when you value control, and a bad one when you just wanted to save nine pounds a month.

Migration has a real cost, paid once, up front. Exporting from a paid tool is deliberately unglamorous. Importers are partial. Formatting, permissions, integrations and links between documents are what break, and you find out three weeks in, after you cancelled. Move one project first and live in it for a fortnight before moving anything that matters.

Some of these are genuinely worse. Not all, and not in the same way. Penpot is a real design tool. Navidrome is a good music server that fundamentally cannot do the thing most people open Spotify for, which is hear something they have not heard before. Graphite is a capable vector editor without the template library that is most of Canva's value. The honest framing is not "this replaces that", it is "this does the part of that you actually use, and you should check which part that is first."

The failure mode with a list like this is switching everything in a weekend and switching most of it back. Pick the one tool you resent paying for the most. Try its twin for a month. Keep the ones that stick.
