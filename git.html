You commented GIT — this is the ladder.

A change has to climb.

Git is four places, not hundreds of commands. A change you type starts in one of them and has to be lifted, deliberately, to each of the next three. Every command you actually use is one of those lifts — which is why the whole thing collapses into four words once you can see the shape.

The whole mental model, one picture

Four places a change can be, and the three lifts between them

The whole mental model, one picture. Everything after it is annotation.

Nº001 · Git is not GitHub

One of them runs on your machine. The other is a website.

Git is a version control system. It lives on your computer, it has no opinion about the internet, and its entire job is remembering every version of your project. GitHub is a website that hosts what Git makes. You can use Git for years without ever creating a GitHub account — the history is already real, already permanent, already on your disk.

The distinction that matters

Only the top rung of the ladder involves GitHub at all. The other three happen entirely on the machine in front of you.

Nº002 · Nothing saves itself

Git tracks everything and stores nothing until you say so

git init turns a folder into a repository, and from that moment Git is watching. But it never commits on your behalf. A file you edited sits in the working directory, changed and unsaved, until you deliberately lift it — which is exactly what git status is telling you every time you run it.

Why staging exists at all

It is the step where you choose. Edit six files, stage two, and the snapshot contains two. Without it, every commit would be everything you happened to have open.

Nº003 · Branch, merge, conflict

Two lines of the same project, folded back together

A branch is a second line of development growing off a commit, so you can build something new without touching the working code. Merging folds it back, and Git does it automatically — right up until both lines changed the same lines of the same file. Then it stops. It marks the disputed section, refuses to guess which version you meant, and waits for you to decide. That refusal is a feature.

On the ladder

Branching and merging both happen on rung 03. They rearrange history; they do not move a change between places.

Nº006 · Going backwards

Three different undos, and only one of them is dangerous

git restore throws away an edit you have not committed. git revert writes a new commit that undoes an old one, erasing nothing — the mistake stays in the history, and so does the correction. git reset moves your branch pointer backwards, which is powerful and therefore very easy to misuse: the commits are usually still there, but the pointer that named them is not.

The habit worth building

Reach for revert by default. It is the only one of the three that is safe on history other people have already pulled.

Ninety percent of the time

Reference · the four commands that do the lifting

CommandWhat it actually does
git addLifts a change from the working directory into staging.
git commitTakes the snapshot. Staging becomes permanent history.
git pushSends your commits up to the remote.
git pullBrings everyone else’s commits down. Run it before you push.
